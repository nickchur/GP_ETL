# pr_std_sql

```sql
pr_std_sql(action text, prm text DEFAULT '', whr text DEFAULT 'true') RETURNS text
```

**Генератор стандартных сервисных / диагностических SQL-запросов.** По короткому
коду `action` (напр. `#table`, `#lock`, `#swf`, `#log`) возвращает **готовый текст
`SELECT`** для мониторинга и аудита объектов и процессов ETL. Сам запрос **не
выполняется** — функция только формирует и возвращает его текст (для последующего
ручного / программного запуска). Неизвестный код → `NULL`.

## Параметры

| Параметр | По умолчанию | Назначение |
|----------|--------------|------------|
| `action` | — | Код запроса (регистронезависим), см. категории ниже |
| `prm` | `''` | Значение подстановки `%1$s` — как правило фильтр по имени объекта (regex `~`); приводится к нижнему регистру. Пусто → без фильтра |
| `whr` | `'true'` | Значение подстановки `%2$s` — дополнительное условие `WHERE`. `'true'` → без доп. фильтра |

## Алгоритм

1. `prm = lower(prm)`.
2. **Нормализация алиасов** действия: `#swf tbl` → `#swf tb`, `#status tbl` → `#status tb`.
3. Большой `CASE lower(action)` выбирает **шаблон запроса** (dollar-quoted `$_$…$_$`) по коду; при отсутствии совпадения → `NULL`.
4. `sql = format(sql, prm, whr)` — подстановка двух позиционных параметров: `%1$s` ← `prm` (фильтр имени), `%2$s` ← `whr` (доп. `WHERE`). Все прочие `%` в шаблонах экранированы как `%%`.
5. `return sql`.

## Категории действий

| Категория | Коды `action` |
|-----------|---------------|
| Сессии / блокировки | `#busy` `#cancel` `#activity`(` all`) `#work` `#todo` `#lock`(` tbl`\|` det`) |
| Super Workflow | `#swf`(` tb`) `#status`(` tb`) `#swf chk` `#rel chk` `#wf`(` all`\|` cancel`\|` last`\|` swf`) `#cwf`(` tb`\|` err`) |
| Логи / ошибки | `#log`(` last`\|` tb`\|` stat`\|` swf`) `#ctl` `#rep` `#err`(` all`\|` tb`) |
| Таблицы / партиции / колонки / объекты | `#table`(` det`\|` std`\|` all`\|` size`\|` sum`\|` det_old`\|` sum_old`) `#part`(` det`\|` cnt`) `#col`(` sht`\|` det`\|` list`\|` def`) `#obj` `#temp` |
| Вьюхи / функции | `#view`(` all`\|` std`\|` def`) `#func`(` def`\|` std`\|` std_def`) `#sdf`(`2`) |
| Качество данных / статистика | `#skew`(` last`\|` hist`) `#ztest` `#fld_stat`(` last`\|` fld`\|` def`) `#vacuum` `#vda`(` tb`) |

### Соглашения по суффиксам кодов

| Суффикс | Смысл |
|---------|-------|
| `tb` / `tbl` | «Сырая» таблица вместо вью |
| `det` | Детально |
| `std` | Системные объекты (`pg_*`, `public`, `information_schema`) |
| `all` | Без фильтра схемы |
| `last` / `hist` | Последний срез / история |
| `def` | DDL-определение объекта |

## Пример

```sql
-- SQL для просмотра таблиц слоя, где имя содержит 'employee', с доп. фильтром
select s_grnplm_vd_hr_edp_srv_wf.pr_std_sql('#table', 'employee', 'schemaname like ''%_stg''');
-- -> готовый SELECT из pg_tables с подставленными %1$s='employee' и %2$s=<условие>
```

> `EXECUTE ON ANY` — может выполняться на любом сегменте Greenplum.
> Диагностические коды `#swf*` / `#wf*` / `#cwf*` дополняют оркестраторы [`pr_swf_start`](pr_swf_start.md), [`pr_swf_start_ctl`](pr_swf_start_ctl.md) и [`pr_swf_wf_group`](pr_swf_wf_group.md).
